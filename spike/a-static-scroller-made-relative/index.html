What moves when a static scroller is given position: relative?

An overlay mounted inside a scroller as an absolutely positioned child lands on the scroller's content origin only if the scroller establishes a containing block, so a library that mounts one has to write position: relative onto a scroller that was static. The specification says that write changes the containing block of the scroller's absolutely positioned descendants and nothing else about layout. Which of the scroller's children move, and whether the ones that move then ride the scroller's own scroll, is what this page measures.

Five children of one static scroller: one in the flow, one absolutely positioned with an inset (its containing block until the write is the .stage outside the panel), one absolutely positioned with every inset auto, one sticky and one fixed. Each is measured, the panel is given position: relative, each is measured again, and then the panel is scrolled to see which ride it.
