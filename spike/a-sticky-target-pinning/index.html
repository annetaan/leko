When is a position: sticky element pinned, and does it say so?

A sticky element rides the scroll until it pins, and from then on it stays against its scrollport's edge while everything under it moves — until its containing block runs out and it is pushed away again. A hole cut where it stood is right in one of those states and wrong in the other, so anything drawing one has to know which state the element is in at the moment of the draw, from one reading and without watching the scroll.

Every panel measures itself. Held is the ground truth and is read the way a viewer would see it: scroll one further pixel and look at whether the element moved. Beside it are three candidate tests, each something a library could ask at the draw, each marked against what held says.

  • offset — the element's box on screen, less where offsetTop puts it. A test only if offsetTop is the flow position; if it moves with the pin, it says nothing.
  • inset — the element's box against its scrollport's edge, less the used top. A pinned element sits exactly on its inset, so this is zero when pinned.
  • static — write position: static, read the box again, put the style back. Exact, and it writes to an element the application owns and flushes layout to do it.

3. A layer that pins to a scroller's scrollport

position: fixed cannot say “the scrollport of that panel”. This can: an absolutely positioned wrapper the size of the scroller's content, holding a position: sticky child at top: 0; left: 0 the size of the scrollport. The wrapper is the child's containing block, so the child pins across the whole range, on both axes, and takes no space in the flow. The red outline is the child, and it should sit exactly on the panel's padding box at every offset. The last row asks whether mounting it grew the scrollable area — a layer that adds overflow to what it covers is no use.

4. Can the pin be predicted from one reading?

A step that wants its target drawn pinned has to be able to scroll to that state, and the destination is not the target's own box. While the element is riding, the distance between its box and its inset is exactly the scroll left before it pins, so the destination is arithmetic on one reading. Each row scrolls to either side of the predicted offset and checks.

6. What a scroller's padding does to both of those

The panels above have none, so the padding box and the content box are the same box in them and nothing there can tell which one a sticky element is held within. This one has padding: 11px, which is what a panel an application owns usually has. Two readings: where a header asking for top: 0 comes to rest, and where the glued layer of question 3 lands — first asking for top: 0; left: 0 the way it did there, then asking the padding back as a negative inset. A layer that lands on the content box leaves the padding of the panel it is dimming undimmed, and a reading taken against the padding box calls a pinned header riding by exactly that padding.
