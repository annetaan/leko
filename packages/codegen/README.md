# @annetaan/leko-codegen

**Write the `reached()` call. Get the name back on `awaits`.**

A [Leko](https://github.com/annetaan/leko) story waits for a name the
application reports.

```ts
leko.reached('order-saved')          // somewhere in your checkout code
{ id: 'save', awaits: 'order-saved' } // in a story, written a month later
```

Both sides are a string, and a string is easy to mistype. Nothing fails when you
do. The step just waits.

This package reads your project, collects every name a `reached()` call reports,
and writes them out as types. After that your editor offers them on `awaits`,
and a name nothing reports stops compiling.

## Use it

```bash
npm install -D @annetaan/leko-codegen
```

With Vite, add the plugin and forget about it. It writes the file before a
build, and keeps writing it while the dev server runs.

```ts
import { lekoSignals } from '@annetaan/leko-codegen/vite'

export default defineConfig({
  // Into src/, or wherever your tsconfig actually reads from.
  plugins: [lekoSignals({ out: 'src/leko-signals.d.ts' })],
})
```

Without Vite, run it.

```bash
leko-signals --out src/leko-signals.d.ts            # once
leko-signals --out src/leko-signals.d.ts --watch    # while you work
leko-signals --out src/leko-signals.d.ts --check    # in CI
```

| Option | |
| --- | --- |
| `--project <path>` | a `tsconfig.json`, or the directory holding one. Default: cwd |
| `--out <path>` | where to write. Default: `leko-signals.d.ts` beside the tsconfig |
| `--loose` | emit the names without promising the list is complete |
| `--check` | write nothing, exit 1 if the file on disk has fallen behind |
| `--watch` | keep writing while the project is edited |

**Put the output where your tsconfig reads from.** A declaration file outside
the project's `include` is compiled by nobody, so the augmentation never applies
and no completion appears. The generator says so when it notices, because
nothing else will.

Commit the generated file. It holds the names alone, sorted, so it changes only
when a signal is added or removed — never because an edit moved a call site.
It costs a diff when the vocabulary changes, and it means
a fresh clone type-checks before anyone has run anything.

## What it writes

```ts
// Generated by @annetaan/leko-codegen. Do not edit.

declare module '@annetaan/leko' {
  interface LekoSignals {
    'order-saved': true
  }

  interface LekoStrict {
    strict: true
  }
}

export type GeneratedByLekoCodegen = true
```

## What it reads

It asks the TypeScript compiler rather than the text, so a name kept in a
constant counts the same as one written at the call site.

```ts
leko.reached('order-saved')          // ✓
leko.reached(ORDER_SAVED)            // ✓  a const, in another file
leko.reached(oneOfTwo)               // ✓  both arms, when the type is narrowed
queue.reached('not-a-signal')        // ✗  a `reached` that is not Leko's
leko.reached(`step-${i}`)            // ✗  listed by `leko-signals` instead
```

The last line is the one to know about. A name built at runtime cannot be
gathered, so the vocabulary is missing it. `leko-signals` prints every call it
could not read, with its file and line. The Vite plugin does not, so a project
on the plugin runs `leko-signals --check` with the plugin's `out` to see them.
**A project with any of those wants `--loose`**, or a hand written block naming
what they report.

```ts
// Anywhere. Declarations merge, and this file is a module because of the export.
declare module '@annetaan/leko' {
  interface LekoSignals {
    'step-1': true
  }
}
export {}
```

## Strict is only about `awaits`

By default the generated file also declares `LekoStrict`, and that is what makes
a name outside the vocabulary fail to compile.

```ts
{ id: 'save', awaits: 'order-svaed' }  // Type '"order-svaed"' is not assignable
```

This is worth doing because the vocabulary came from the call sites. A name in
`awaits` that is missing from it is a step waiting for a report nothing makes,
which is a bug rather than a naming preference.

**`reached()` is never tightened, with or without it.** A `reached()` call is
instrumentation meant to stay in the source permanently, including in builds
where no tour ever runs. A type error there would talk people into deleting the
call, and the call is where the vocabulary comes from in the first place.

`--loose` drops the promise and keeps the completion.
