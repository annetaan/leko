Everything below is this page. The tour points at the sidebar on the left, or
at the menu button that opens it when the window is too narrow to show it, then
at the code block further down, and at a field you type into while the overlay
is up. Nothing is in an iframe and nothing is a screenshot. There are two ways
in — the button below, or the front page's own tour, which hands this one on
across the page load.

## What the tour is doing

Which story starts depends on the width of the window. Each intro is one step
and names `thisPage` as `next`, so either way the tour goes on to the same three
steps. Narrow or widen the window past the breakpoint while an intro is showing
and the page stops it and starts the other one. Once the tour is past the intro
it is left alone, because everything else it points at shows at both widths.

Three of the four steps you see carry a next control. The name step does not,
and there is no way to configure that: it declares `awaits`, so the only thing
that moves it on is the page reporting that the field was filled in.

<div data-tour-source>

```ts
const thisPage = {
  id: 'this-page',
  steps: [
    { id: 'source', target: '[data-tour-source]', message: '…' },
    {
      id: 'name',
      target: '[data-tour-input]',
      message: '…',
      awaits: 'name-entered',
    },
    { id: 'done', target: '[data-tour-start]', message: '…' },
  ],
} satisfies LekoStory

const desktopIntro = {
  id: 'desktop-intro',
  steps: [{ id: 'sidebar', target: '#starlight__sidebar', message: '…' }],
  next: thisPage,
} satisfies LekoStory

const mobileIntro = {
  id: 'mobile-intro',
  steps: [{ id: 'menu', target: 'starlight-menu-button button', message: '…' }],
  next: thisPage,
} satisfies LekoStory

const introFor = () => (matchMedia('(min-width: 50rem)').matches ? desktopIntro : mobileIntro)

button.addEventListener('click', () => leko.start(introFor()))

leko.pickUp([desktopIntro, mobileIntro]) // once, as the page loads — it takes what the front page handed on, or nothing
```

</div>

The listener on the field belongs to the page, and it reports rather than
advances.

```ts
input.addEventListener('input', () => {
  if (input.value.trim() !== '') leko.reached('name-entered')
})
```

Delete that line and the tour stops at the name step for ever. That is the
point of it. The tour moves because the application said something was true.

What `pagehide` keeps in `sessionStorage` is the pattern, the successor's
id, and the URL it was kept at. The next document reads all three once: the
pattern and the kept URL decide whether to start at all, and the id says
what to start — nothing but the id reaches the story it starts. A reload of
this page starts nothing, because this story's last step waits for no URL,
so `pagehide` keeps nothing to hand on.
