## What the tour is doing

Two of the four steps carry a next control. The third one does not, and there is
no way to configure that: it declares `awaits`, so the only thing that moves it
on is the page reporting that the field was filled in.

<div data-tour-source>

```ts
const thisPage = {
  id: 'this-page',
  steps: [
    { id: 'sidebar', target: '#starlight__sidebar', message: '…' },
    { id: 'source', target: '[data-tour-source]', message: '…' },
    {
      id: 'name',
      target: '[data-tour-input]',
      message: '…',
      awaits: 'name-entered',
    },
    { id: 'done', target: '[data-tour-start]', message: '…' },
  ],
} satisfies LekoStory

button.addEventListener('click', () => leko.start(thisPage))

leko.pickUp([thisPage]) // once, as the page loads — it takes what the front page handed on, or nothing
```

</div>

The listener on the field belongs to the page, and it reports rather than
advances.

```ts
input.addEventListener('input', () => {
  if (input.value.trim() !== '') leko.reached('name-entered')
})
```

Delete that line and the tour stops at the third step for ever. That is the
point of it. The tour moves because the application said something was true.

What `pagehide` keeps in `sessionStorage` is the pattern, the successor's
id, and the URL it was kept at. The next document reads all three once: the
pattern and the kept URL decide whether to start at all, and the id says
what to start — nothing but the id reaches the story it starts. A reload of
this page starts nothing, because this story's last step waits for no URL,
so `pagehide` keeps nothing to hand on.
